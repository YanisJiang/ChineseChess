# 陪练一着多谱直出 + 屏风网离谱着清洗

日期：2026-11-05  
状态：设计待审（实现前需用户确认本文件）  
关联对话：此前「屏风短谱网拼完整示范局」体验后的交互与内容修正

## 目标

1. **一着双/多谱**：棋盘上直接行棋即可，不再「先选中再走」。
2. **谱面清洗**：趁谱面尚少，整网去掉无计划送吃、硬凑杀、硬凑和；其引出的后续谱一并清除。终局通路不再硬保。

## 非目标

- 不追求红胜 / 黑胜 / 和棋三条完整终局（谱够多后自然接得上即可）。
- 不改人机 `openingBook.ts`。
- 不新建审谱引擎/批量打分炉子；人工按规则过一遍现有屏风网。
- 本轮不强制对齐学棋模式侧栏（学棋点变招已是点即走）；若改动极小可顺带统一文案，不扩范围。
- 不为「实用化」整网推倒重做；以清洗 + 枢纽短改为主。

## 一、陪练一着多谱交互

### 规则

棋盘走出一手 `uci` 后：

| 情况 | 行为 |
|---|---|
| ① 当前课在上一局面仍有该 `uci` 的后续 | **不转谱**，继续执行当前谱 |
| ② 当前课无后续（谱尽，或该着不在本谱），且该着可进其它课 | **按 `findOneMoveEntries` 原序取第一条**转入对应谱 |

侧栏「走 X 可进入《Y》」：

- **立即转入 Y，并自动走该 `uci` 一步**
- 不再「只点选、等棋盘再走」

### 实现要点（相对现状）

- 去掉「一着多谱必须先 `preferredUci` / `coachTransfer` 点选才转」的门闩。
- 转谱判定改为：本谱该着仍有续 → 留本谱；本谱无续 → `firstCrossLineIdForUci`（或等价按序第一条）。
- `selectCoachCrossEntry`：转谱 + `beginMove`（局面已在目标根且只需挂课的边界仍可立即转，但主路径是走子）。
- UI 文案去掉「点选后再走」类说明。
- `preferredUci` 可保留作谱内多变招高亮/提示，但**不得**再挡住棋盘直出或强制「先选才能贴谱」。

| `src/study/transferIntent.ts` | 若需抽出「本谱有续 vs 无续」判定则小改；否则可只在 App 用现有 API |

## 二、屏风短谱网清洗

### 判定标准

| 清 | 留 |
|---|---|
| 无补偿、无计划的送吃 | 弃子抢先、诱敌等有战术/战略目标的弃子 |
| 为演示硬编的凑杀 | 兑子 |
| 为演示硬编的凑和（含无意义循环凑三次重复） | 说得通的短计划，到「可转谱/告一段落」即可 |

### 范围与动作

- **保留**：`PINGFENG_SHARED`（至车一平二）及打中兵、兑马后续挺兵等常见计划段（若其中个别离谱着再点名删）。
- **删除或截断**：由 `PINGFENG_RED_TAIL` / `BLACK_TAIL` / `DRAW_TAIL` 生成的后续课（下卒出车→沉底取势、肋车入局、局面循环等），以及枢纽通向这些尾巴的无计划送吃主线。
- **改写枢纽**「屏风平车后」：只留有计划的短分支；不追求杀/和。
- **测试**：去掉「三路必须终局」类断言；改为清洗后课合法、关键衔接可挂、已知离谱尾巴不存在。

### 涉及文件（预期）

|---|---|
| `src/study/pingfengWeb.ts` | 删尾巴 / 改枢纽 / 更新导出 |
| `src/study/catalog.ts` | 随导出列表自动或手动对齐 |
| `src/study/pingfengWeb.test.ts` 等 | 验收断言改写 |
| 旧设计 `2026-11-05-pingfeng-short-line-web-design.md` | 标注「终局三路」目标被本设计废止/降级，避免两份 spec 打架 |

## 三、验收

1. 陪练：同一着可进多谱时，棋盘直出符合 ①②；侧栏点击进入目标谱并自动走一步。
2. 无「必须先点选才能走/转」的门闩与对应误导文案。
3. 屏风网中无已知「下卒送吃凑局」「循环凑和」类尾巴课；枢纽分支说得通且短。
4. 相关单测通过；不新增业务后门式测试钩子。

## 四、风险与回退

- **风险**：砍尾巴后「一局走完」变短——已接受。人工误判可能多删有计划弃子——按「有疑义则留、点名再议」。
- **回退**：交互与谱面分两块回退点；谱面可整文件回退 `pingfengWeb.ts`。
